# 0030 — Manifiesto de runtime y requisitos bloqueados por plataforma y perfil
- Estado: Hecha
- Paso del pipeline: 0
- Depende de: 0028, 0029
- ADRs: 0001, 0004, 0009; preguntas/0012 (opción C)
- Spec UX: docs/ux/01-primer-arranque.md (las cifras `{n}` salen de aquí)

## Objetivo
Generar los archivos de requisitos fijados por perfil y escribir el manifiesto real `app/resources/runtime-manifest.json` con los datos medidos en la tarea 0005 §9, marcando el modelo Rápido como provisional con licencia no declarada.

## Criterios de aceptación
- [x] `worker/scripts/compilar_requisitos.py` genera `worker/requisitos/{darwin-arm64-mps,darwin-x64-cpu,win32-x64-cpu,win32-x64-cuda,linux-x64-cpu,linux-x64-cuda}.txt` con `uv pip compile` (ADR 0009 §1): Python 3.12, `--generate-hashes`, índices emitidos, *extra* `separacion`, versiones exactas (`audio-separator==0.48.0`; torch por perfil: la última que publique cada índice y sea compatible; `onnxruntime`, `audioread` y `onnx-weekly`/`onnx` fijados por *override*). Modo `--comprobar` que falla si algún archivo no coincide con lo que generaría. Si una combinación no resuelve, el script falla con un mensaje claro (y se anota aquí).
- [x] Cada archivo incluye un comentario de cabecera con la orden exacta que lo generó.
- [x] `app/resources/runtime-manifest.json` válido contra `shared/manifiesto.ts` (0029), con: `python` 3.12.16 (24 MB en darwin-arm64, medido; el resto, del tamaño publicado de python-build-standalone); `runtime` con los `bytes_descarga`/`bytes_disco` de 0005 §1 y §9 (`medido: true` solo en darwin-arm64), `espacio_requerido` (CPU 3 GB, Apple Silicon 4 GB, NVIDIA 10 GB) y `sha256_requisitos` de cada archivo; `modelos` con archivo, URLs (espejo y origen), bytes y SHA-256 de 0005 §4 (incluido el yaml de Calidad); Rápido con `licencia: "no declarada"`, `provisional: true`; Calidad con `licencia: "MIT"`; `factores` medidos del M1 y `null` + estimación del ADR 0004 para x86 y CUDA.
- [x] Test (Vitest) que valida el manifiesto, que todos los archivos de requisitos referenciados existen y que su SHA-256 coincide con `sha256_requisitos` (si alguien regenera los requisitos sin actualizar el manifiesto, falla).
- [x] Opcional con red (`pesado`, se omite en CI): test que hace `HEAD` a cada URL de modelo y comprueba `Content-Length` = `bytes`.
- [x] CI: el job del worker ejecuta `compilar_requisitos.py --comprobar` (solo resolución, sin descargar wheels grandes; si `uv pip compile` necesita descargar metadatos, usar la caché de uv). Si resulta demasiado lento o frágil, dejarlo en el workflow manual de 0040 y anotarlo.
- [x] `THIRD_PARTY_NOTICES.md`: audio-separator (MIT), PyTorch (BSD-3), ONNX Runtime (MIT) y la nota del modelo Rápido sin cambios respecto a 0012.

## Notas de implementación
- **Qué se hizo**: `worker/scripts/compilar_requisitos.py` (solo biblioteca estándar; usa el `uv` del PATH o de `UV`) genera `worker/requisitos/{darwin-arm64-mps,win32-x64-cpu,win32-x64-cuda,linux-x64-cpu,linux-x64-cuda}.txt` y tiene `--comprobar`, `--actualizar` y `--perfil`. Cada archivo lleva una cabecera con la orden de `uv pip compile` (uv 0.13.7, Python 3.12, `--generate-hashes --emit-index-url`, extra `separacion`) y los *overrides* (`torch==…` por perfil, `onnxruntime==1.31.1`, `audioread==3.1.0`, `onnx-weekly==1.24.0.dev20261102`). Versiones resueltas: torch 2.15.0 en macOS (PyPI) y 2.15.0+cpu (índice `cpu`); 2.11.0+cu128 (índice `cu128`) con torchvision 0.26.0+cu128. `app/resources/runtime-manifest.json` (versión 1) con los datos de 0005 §1, §4 y §9; test `app/src/shared/manifiestoReal.test.ts` (válido, existencia y SHA-256 de cada requisito, modelos, factores; HEAD de las URLs con `SHINOBI_TESTS_RED=1`, comprobado: las 5 URLs coinciden en `Content-Length`); `worker/tests/test_compilar_requisitos.py`; paso en el job `worker` de `.github/workflows/ci.yml`; `THIRD_PARTY_NOTICES.md`; `worker/README.md`.
- **Hallazgos**:
  1. **`darwin-x64-cpu` no resuelve** (torch >= 2.3 no tiene ruedas para macOS Intel; audio-separator 0.48.0 lo exige). El script lo omite con un mensaje claro y el manifiesto no tiene `darwin-x64` (`requisitosDe` → `null`, B6). Pregunta `preguntas/0015` (también: Apple Silicon necesita **macOS 14**, no 12).
  2. `--python-platform aarch64-apple-darwin` supone macOS 13 y no encuentra torch/onnxruntime (`macosx_14_0_arm64`). Para `darwin-arm64-mps` el script resuelve en modo `--universal` con un `[tool.uv] environments` (macOS arm64, Python 3.12) en una copia temporal de `pyproject.toml`: por eso las líneas de ese archivo llevan marcadores de entorno (`; python_full_version < '3.13' and platform_machine == 'arm64' and sys_platform == 'darwin'`), que uv evalúa al instalar. Se comprobó `uv pip install --dry-run --require-hashes` en este Mac (macOS 26) y con `--python-platform` para Windows y Linux.
  3. `--emit-index-url` no emite el índice de `--torch-backend`: el script añade `--extra-index-url https://download.pytorch.org/whl/<cpu|cu128>`. La instalación (0034) **debe** usar `--index-strategy unsafe-best-match` (o `UV_INDEX_STRATEGY`); con el predeterminado uv buscaría todos los paquetes primero en el índice de PyTorch. Los hashes (`--require-hashes`) mitigan la confusión de dependencias.
  4. En Windows `audio-separator` resuelve `diffq-fixed` (rueda binaria) en lugar de `diffq`; en macOS y Linux sigue siendo `diffq==0.2.4` (en macOS, sin rueda: se compila desde *sdist* al instalar, 0005). Los perfiles CUDA usan `audio-separator[cpu]` y `onnxruntime` de CPU (ONNX en GPU no está previsto).
  5. `--comprobar` reutiliza como preferencia las versiones ya escritas, de modo que no falla cuando PyPI publica versiones nuevas; `--actualizar` las vuelve a resolver (hay que subir `version` y los SHA del manifiesto).
- **Decisiones**: `requisitos` del manifiesto es la ruta relativa a la raíz del repo o de `resources/` (`worker/requisitos/<x>.txt`; 0025 debe copiarlos a `resources/worker/requisitos/` junto con el código del worker). `bytes_descarga` de `runtime` no incluye Python (se suma aparte; 296 MB macOS, 311 MB / 3,1 GB Windows, 434 MB / 4,4 GB Linux, de 0005 §1); `bytes_disco` 1,28 GB solo en macOS (medido). Python: 24 MB (darwin-arm64, medido), 22 014 416 B (Windows) y 34 505 639 B (Linux) del `install_only_stripped` de python-build-standalone 20261026. Factores: `mps` = M1 (Calidad 1,08–1,27 y Rápido 0,70–0,79, ambos en CPU: la app no usa MPS, `preguntas/0010`); `cpu` y `cuda` con `null` y la estimación del ADR 0004 en `estimacion`. El perfil `mps` es el único de Apple Silicon.
- **Cómo probarlo**: `cd worker && uv run python scripts/compilar_requisitos.py --comprobar && uv run pytest`; `cd app && npx vitest run src/shared/manifiestoReal.test.ts` (con `SHINOBI_TESTS_RED=1` también hace los HEAD).
- **Deuda**: los archivos de Windows y Linux solo se han resuelto, no instalado (0040); CI no ha ejecutado aún `--comprobar` en los tres SO (una resolución distinta por SO sería un fallo a revisar). Los archivos pesan ~140 KB cada uno.
