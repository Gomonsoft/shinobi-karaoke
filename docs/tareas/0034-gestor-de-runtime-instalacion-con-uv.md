# 0034 — Gestor de runtime: secuencia de instalación con uv, progreso, pausa y errores
- Estado: Hecha
- Paso del pipeline: 0
- Depende de: 0013, 0031, 0032, 0033
- ADRs: 0001, 0004, 0006, 0009
- Spec UX: docs/ux/01-primer-arranque.md (B2, B4, B5; criterios 3–7 y 10)

## Objetivo
El núcleo del primer arranque en el proceso principal (`app/src/main/runtime/gestor.ts`): ejecutar las 5 fases técnicas de `arquitectura.md` §6 de forma idempotente y reanudable, agruparlas en las 3 fases visibles de `ux/01`, emitir progreso con ETA y traducir los fallos a los códigos de error del catálogo.

## Criterios de aceptación
- [x] Fases técnicas, cada una con su comprobación "ya hecha" para saltarla (ADR 0009 §6.3):
  1. **Plataforma**: de 0031; plataforma no soportada → `PLATAFORMA_NO_SOPORTADA`. Incluye `darwin` con `process.getSystemVersion()` < 14 (ADR 0009 Revisiones, `preguntas/0015`); si 0031 ya lo comprueba, basta con reutilizarlo y cubrirlo con un test.
  2. **Motor** (`motor`): `uv python install cpython-3.12.16-<so>-<arq>-none` y `uv venv --python <ruta de ese intérprete> runtime/venv`, con la **arquitectura de la plataforma real** de 0031, siempre explícita: bajo Rosetta se instala Python aarch64 y el worker se ejecuta nativo (ADR 0009 Revisiones, `preguntas/0014` §2). El marcador guarda la plataforma real. con el entorno aislado del ADR 0009 §3 (`--no-config`, `UV_CACHE_DIR`, `UV_PYTHON_INSTALL_DIR`, `UV_PYTHON_PREFERENCE=only-managed`, sin heredar `VIRTUAL_ENV`/`PYTHONPATH`/`UV_*`).
  3. **Componentes** (`componentes`): `uv pip install --python <venv> --require-hashes --index-strategy unsafe-best-match -r <requisitos del perfil previsto>` (**obligatorio** `--index-strategy unsafe-best-match`, o `UV_INDEX_STRATEGY` en el entorno aislado: los archivos llevan `--extra-index-url` del índice de PyTorch y con la estrategia por defecto uv buscaría todos los paquetes primero en ese índice; hallazgo 3 de 0030, ADR 0009 Revisiones; el test del uv falso comprueba el argumento); al terminar escribe `runtime/instalado.json` (marcador) y ejecuta `uv cache clean`.
  4. **Diagnóstico** (subestado de componentes, "Comprobando tu equipo…"): `diagnostico` (0032) con el intérprete del venv recién creado y `PYTHONPATH` al código del worker (empaquetado: `resources/worker`; sin empaquetar: `<repo>/worker`). Guarda `perfil_hardware`, `hardware` y `motivo_rebaja`; si rebaja, el modelo pasa a Rápido y el total se recalcula.
  5. **Modelo** (`modelo`): `descargarModelo` (0033) del modelo del perfil final; al terminar, `separacion.modelos_descargados`.
  Al final, `instalacion.estado = "completa"` y `version_manifiesto`. Cada cambio de fase se persiste en `config.instalacion.fases` (0008), así que cerrar a mitad y reabrir continúa desde la fase pendiente.
- [x] Puerto `EjecutorUv` (ADR 0009 §8): lanza uv con `shell: false`, sin `stdin`, con `AbortSignal` y matando el árbol de procesos igual que 0013 (`detached` + grupo en POSIX, `taskkill /T /F` en Windows); stdout/stderr van a `registros/runtime-<fecha>.log` y se guardan las últimas 50 líneas para "Copiar detalles".
- [x] **Progreso** (evento interno `{ faseVisible, estados, bytes, total, totalGlobal, porcentajeGlobal, etaSegundos, modo, motivoRebaja }`, ≤ 4/s): motor = crecimiento de `runtime/python` + caché frente a `python.bytes` del manifiesto; componentes = crecimiento de `runtime/cache-uv` frente a `bytes_descarga` (medición del directorio cada 500 ms, como mucho 99 % hasta terminar, nunca retrocede); modelo = bytes exactos. Barra total ponderada por bytes; tras una rebaja, el total baja pero el porcentaje mostrado no retrocede (`ux/01` criterio 5b). ETA reutilizando `EstimadorProgreso` (0014) con 10 s sin ETA (no 15 s) y como mucho un cambio por segundo.
- [x] **Errores**: clasificación del stderr de uv con fixtures reales capturados (sin red: DNS/conexión → `SIN_CONEXION`; `No space left on device` / `os error 28` / Windows `os error 112` → `SIN_ESPACIO`; HTTP 5xx/429/`timed out` repetido → `SERVICIO_NO_DISPONIBLE`; hash que no coincide → `VERIFICACION_FALLIDA`; resto → `ERROR_INTERNO`). Antes de cada fase se vuelve a comprobar el espacio libre frente a lo que falta (→ `SIN_ESPACIO` sin lanzar uv). El error se guarda en `instalacion.error` con su fase; las fases completadas no se repiten al reintentar.
- [x] **Pausar** (`pausar()`): cancela el proceso o la descarga en curso, deja la fase en `pendiente` (no `error`), conserva lo descargado y resuelve cuando no queda ningún proceso hijo. Un `reintentar()`/`instalar()` posterior continúa.
- [x] Una única instalación a la vez (llamadas concurrentes devuelven la misma promesa).
- [x] Tests unitarios con dobles de los puertos: secuencia completa; reanudación tras cerrar en cada fase; rebaja `cuda` → `cpu` con recálculo del total sin retroceso; fallo en componentes y reintento sin repetir motor; pausa sin procesos vivos; clasificación de cada fixture de stderr; espacio insuficiente antes de una fase. Test de integración con un **uv falso** (script Node que imita las órdenes y escribe archivos) para comprobar argumentos y variables de entorno exactas que recibe uv (incluida la petición de Python con arquitectura explícita, también simulando Rosetta).
- [ ] Prueba manual documentada (no CI): instalación real en la máquina del programador con `SHINOBI_DATOS` temporal; anotar tiempos y tamaños reales en las notas.

## Notas de implementación
- **Qué se hizo**: `app/src/main/runtime/gestor.ts` (`crearGestorRuntime`: `instalar`/`reintentar`/`pausar`/`instalando`/`suscribir`; puertos `Diagnosticador`, `DescargadorModelos`, `MedidorDirectorio` y reutiliza `EjecutorUv`, `EspacioLibre` y `ServicioDeteccion`), `uv.ts` (`crearEjecutorUv` real con `detached`/`taskkill` vía `terminarArbol`, ahora exportado de `trabajos/worker.ts`; `entornoUv`; `clasificarStderr`; `ErrorRuntime`), `index.ts` reexporta `modelos`, `uv` y `gestor`. Marcador `runtime/instalado.json` (`leerMarcador`, exportado para 0035). Orden de uv: `python install` → `python find` (ruta del intérprete) → `venv --clear --python <ruta>` → `pip install --require-hashes --index-strategy unsafe-best-match -r` → marcador → `cache clean` → diagnóstico → modelo. Todas las órdenes llevan `--no-config` y la petición de Python usa la arquitectura real (`cpython-3.12.16-macos-aarch64-none`, también bajo Rosetta).
- **macOS < 14** (`preguntas/0015`): `deteccion.ts` — `plataformaActual(real, manifiesto, versionSo)` devuelve `null` para darwin < 14 *después* de comprobar el manifiesto; `motivoNoSoportada()` devuelve `'arquitectura'` (primero) o `'so_antiguo'`; `entornoReal` usa `process.getSystemVersion()` (versión de macOS) en Electron en vez de `os.release()`. Tests con 13.6 / 14.0 y Mac Intel 13.6 → `arquitectura`.
- **Decisiones**: `EstimadorProgreso` admite umbral configurable (10 s aquí, 15 s por defecto). Progreso: motor = `runtime/python`+`cache-uv`, componentes = `cache-uv` (menos lo residual del motor), modelo = bytes exactos; máx. 99 % por fase y global hasta terminar; porcentaje global nunca retrocede tras la rebaja; emisión ≤ 4/s y ETA con un cambio por segundo. Espacio: antes de motor/componentes se exige `espacio_requerido` menos lo ya ocupado en `runtime/`; antes del modelo, sus bytes menos lo ya descargado. Los fallos persisten `instalacion.error` con la fase (`plataforma` si falla la comprobación previa); pausar deja la fase en `pendiente`. Fixtures de stderr en `runtime/__fixtures__/uv-stderr/`: DNS, conexión rechazada, Python sin DNS y hash incorrecto **capturados con uv 0.13.7 real**; 503, 429, timeout y `os error 28`/`112` son reconstruidos a partir del formato documentado de uv (no se pudieron provocar aquí).
- **Cómo probarlo**: `cd app && npx vitest run src/main/runtime` (`gestor.test.ts` con dobles, `gestor.integracion.test.ts` con uv falso Node que comprueba argumentos y entorno exactos, `uv.test.ts`).
- **Deuda / pendiente**: prueba manual de instalación real **no realizada** en esta intervención (se descargarían ~300 MB + 913 MB de modelo); queda para 0040 o una sesión con `SHINOBI_DATOS` temporal, anotando tiempos y tamaños. El cableado IPC, `limpiarModelos` al arrancar y el uso de `app.runningUnderARM64Translation` son de 0035/0036. `prettier --write src/main` reformateó de paso archivos ajenos sin cambios de lógica.
