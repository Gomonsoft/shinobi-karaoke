# 0029 — Contratos compartidos de la Fase 2: manifiesto, resultados del worker, URL de YouTube, errores y config
- Estado: Hecha
- Paso del pipeline: 0 y 1
- Depende de: 0006, 0013
- ADRs: 0003, 0004, 0006, 0009
- Spec UX: docs/ux/01-primer-arranque.md, docs/ux/03-anadir-cancion.md (validación local del enlace)

## Objetivo
Fijar en `app/src/shared/` (Zod, ADR 0007) todo lo que comparten main, renderer y worker en la Fase 2, para que las tareas de worker, main y renderer puedan avanzar en paralelo.

## Criterios de aceptación
- [x] `shared/manifiesto.ts`: esquema del manifiesto de runtime del ADR 0009 §2 (`version`, `python`, `runtime[plataforma][perfil]`, `modelos[]` con `licencia` y `provisional`, `factores`), tipos inferidos y funciones puras: `modeloDelPerfil(perfil)`, `requisitosDe(manifiesto, plataforma, perfil)` (o `null` si la plataforma no está soportada), `bytesTotalesInstalacion(...)`, `estimarMinutosSeparacion(duracionMs, perfil, modo, factoresMedidos, manifiesto)` → `{ min, max }` (factor medido si existe; si no, el de referencia; si es `null`, la estimación).
- [x] `shared/youtube.ts`: `analizarUrlYoutube(texto)` → `{ ok: true, idVideo, urlCanonica } | { ok: false, codigo: 'URL_NO_VALIDA' | 'URL_NO_SOPORTADA' }`. Acepta `youtube.com/watch?v=`, `m.youtube.com`, `youtu.be/`, `music.youtube.com/watch`, `/shorts/`, con o sin `www`/esquema y con parámetros extra (`t`, `si`, `feature`); rechaza `list=` sin `v` y `/playlist` (`URL_NO_SOPORTADA`), `/live/` (`URL_NO_SOPORTADA`), otros hosts, credenciales/puertos, `javascript:`, más de 2048 caracteres e id que no sea `[A-Za-z0-9_-]{11}`. Un `watch?v=…&list=…` se acepta como vídeo (se ignora la lista, `noplaylist`). Tabla de casos en el test (≥ 25).
- [x] `shared/protocolo.ts`: esquemas de `datos` del mensaje `resultado` para `importar-archivo` (`duracion_ms`, `metadatos {titulo, artista, album}`, `ganancia_db`, `lufs`, `nombre_original`, `mezcla`), `info-youtube` (`id_video`, `titulo_original`, `canal`, `duracion_s`, `metadatos` sugeridos, `miniatura_jpeg_base64` opcional), `descargar-youtube` (como `importar-archivo` + `bytes_descargados`) y `diagnostico` (`perfil`, `dispositivo`, `gpu`, `vram_mb`, `motivo_rebaja: null | 'memoria' | 'generico'`, versiones de torch/onnxruntime). Fases de progreso nuevas documentadas: `preparando`, `descargando`, `actualizando`.
- [x] `shared/errores.ts`: añadir `VERIFICACION_FALLIDA` y `PLATAFORMA_NO_SOPORTADA` al catálogo (el fallo de servidor reutiliza `SERVICIO_NO_DISPONIBLE`). El catálogo Python de `worker/shinobi_worker/errores.py` se mantiene igual (test que compara ambas listas leyendo el archivo TS, o lista duplicada con test de igualdad).
- [x] `shared/config.ts` (campos nuevos con valor por defecto, sin subir `esquema`, ADR 0006): `instalacion.perfil_previsto` (`cpu|cuda|mps|null`), `instalacion.motivo_rebaja` (`null|memoria|generico`), `instalacion.error` (`{codigo, mensaje, fase} | null`), `instalacion.version_manifiesto` (`number|null`). Una config antigua sin ellos se lee igual (test).
- [x] Tests unitarios de todo lo anterior; `npm run typecheck`, `lint` y `test` pasan.

## Notas de implementación
- **Qué se hizo**: `shared/manifiesto.ts` (esquema Zod con `plataforma`/`perfil`/`modelo`, `modeloDelPerfil`, `requisitosDe`, `bytesTotalesInstalacion` = Python + dependencias + modelo del perfil con extras, `estimarMinutosSeparacion` → `{min,max}` o `null` sin datos; añade el campo `estimacion[perfil][modo]` del ADR 0004 junto a `factores`); `shared/youtube.ts` (`analizarUrlYoutube`, tabla compartida en `shared/__fixtures__/youtube-urls.json` con 47 casos, para que 0047 la lea desde Python); `shared/protocolo.ts` (esquemas de resultado de `importar-archivo`, `info-youtube`, `descargar-youtube`, `diagnostico`, y `FASES_PROGRESO`); `errores.ts` (+`VERIFICACION_FALLIDA`, `PLATAFORMA_NO_SOPORTADA`); `config.ts` (`instalacion.perfil_previsto`, `motivo_rebaja`, `error`, `version_manifiesto`, sin subir `esquema`); `index.ts` reexporta manifiesto y youtube.
- **Decisiones**: `mezcla` en el resultado de importar es la ruta relativa al directorio de la canción (`fuente/mezcla.flac`). `lufs` admite `null` (silencio). `instalacion.error.fase` es una cadena libre (0034 decide los nombres de las fases técnicas). Un puerto explícito (incluso `:443`) o credenciales → `URL_NO_VALIDA`. `youtube.com/watch` sin `v` pero con `list` → `URL_NO_SOPORTADA`; `/playlist` y `/live/<id>` → `URL_NO_SOPORTADA`; el resto de rutas (`/@canal`, `/channel/…`) → `URL_NO_VALIDA`.
- **Catálogo Python**: se añadió la tupla `CODIGOS_ERROR` a `worker/shinobi_worker/errores.py` (lista duplicada) y un test de Vitest (`protocolo.test.ts`) que lee ese archivo y comprueba la igualdad con `errores.ts`.
- **Cómo probarlo**: `cd app && npx vitest run src/shared`; `npm run typecheck`, `lint`, `format:check`.
- **Deuda**: el manifiesto real y su test (existencia/SHA de requisitos) son de 0030; 0047 debe leer `youtube-urls.json` en su test de Python.
