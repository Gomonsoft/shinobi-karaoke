# 0047 — Worker: comando `info-youtube` (metadatos, miniatura JPEG con PyAV y errores) y adaptador `FuenteYoutube`
- Estado: Hecha
- Paso del pipeline: 1
- Depende de: 0028, 0029
- ADRs: 0003 (YouTube, metadatos, miniatura en JPEG con PyAV, revisiones 2026-11-04), 0009 §7–§8
- Spec UX: docs/ux/03-anadir-cancion.md (wireframe C, vista previa, errores de YouTube)

## Objetivo
Obtener en 2–5 s, **sin descargar el audio**, lo necesario para la vista previa: título original, canal, duración, miniatura y metadatos sugeridos, con errores diferenciados.

## Criterios de aceptación
- [x] `shinobi_worker/youtube.py` con una interfaz `FuenteYoutube` (`info(url)`, `descargar(url, destino, al_progreso)`) y su implementación real con la API Python de yt-dlp: `noplaylist=True`, `skip_download` para la info, sin postprocesadores, sin cookies, `js_runtimes` apuntando al Deno del paquete PyPI (ADR 0009 §5), `quiet` con un *logger* propio que reenvía a `log` del protocolo (nada de yt-dlp en stdout).
- [x] `python -m shinobi_worker info-youtube --args '{"url": "..."}'`: vuelve a validar la URL (mismas reglas que `shared/youtube.ts` de 0029; tabla de casos compartida como fixture JSON leída por ambos tests) → `URL_NO_VALIDA`; `_type == "playlist"` o `is_live`/`was_live` con `live_status` de directo o `is_upcoming` → `URL_NO_SOPORTADA`.
- [x] Metadatos sugeridos (ADR 0003): `track`/`artist`/`album` si existen; si no, `title` partido por " - " (o " – ", " — ") y limpiado de sufijos (`(Official Video)`, `(Official Music Video)`, `[Official Audio]`, `(Lyrics)`, `[Lyric Video]`, `(Audio)`, `(Video oficial)`, `(Letra)`, `HD`/`4K`, `ft./feat. …` al final del título; insensible a mayúsculas), y como artista `artist` o `channel`/`uploader` sin `- Topic`/`VEVO`/`Official`. Tabla de ≥ 20 casos en el test.
- [x] Miniatura: elige la miniatura más pequeña con ancho ≥ 320 de `thumbnails` (o `thumbnail`), la descarga con el *opener* de yt-dlp (`urlopen`, plazo 10 s), la decodifica con PyAV y la **codifica a JPEG** (`mjpeg`, calidad ~85, redimensionada a 320 px de ancho como máximo, ≤ ~40 KB) sin `ffmpeg` ni `--convert-thumbnails`; resultado en `miniatura_jpeg_base64`. Si falla cualquier paso → sin miniatura (no es error; `log` de aviso). La conversión es una función pura probada con imágenes WebP, PNG y JPEG generadas en el test.
- [x] Clasificación de errores de yt-dlp en una función pura probada con mensajes reales de fixtures (texto de `DownloadError`/`ExtractorError`): privado, eliminado, "Video unavailable", restricción de edad ("Sign in to confirm your age"), región → `VIDEO_NO_DISPONIBLE`; "Sign in to confirm you're not a bot", HTTP 403/429, fallo de extracción/firma (`nsig`, "Unable to extract") → `YOUTUBE_BLOQUEADO` con `reintentable: true`; errores de red (`URLError`, DNS, conexión rechazada, *timeout*) → `SIN_CONEXION`; resto → `ERROR_INTERNO`.
- [x] **Doble** `FuenteYoutubeFalsa`: activo solo si el worker recibe `SHINOBI_YTDLP_FALSO=<dir>` en su entorno; `info` lee `<dir>/<id_video>.json` (o un error simulado `{ "error": "<mensaje yt-dlp>" }`) y la miniatura de `<dir>/<id_video>.webp|jpg` si existe. Fixtures sintéticas en `worker/tests/fixtures/youtube/` (JSON escrito a mano con la forma de `extract_info`, sin datos de vídeos reales con copyright; miniaturas generadas).
- [x] Tests (CI, sin red): validación, metadatos, miniatura, clasificación, y el comando de punta a punta con el doble. Test `red` (se omite en CI) contra un vídeo real de licencia libre o dominio público elegido por el programador (anotar URL y licencia aquí).

## Notas de implementación
- **Qué se hizo**: `worker/shinobi_worker/youtube.py` (validación de URL con las mismas reglas que `shared/youtube.ts`, `clasificar_error`, protocolo `FuenteYoutube` con `info`/`descargar`/`obtener_miniatura`, `FuenteYoutubeReal` con yt-dlp y Deno del paquete PyPI, `FuenteYoutubeFalsa`, comando `info_youtube`), `metadatos_youtube.py` (heurística) y `miniatura.py` (elegir, convertir a JPEG con PyAV `mjpeg`, 320 px, sin ffmpeg). Registrado como `info-youtube` en `comandos.py`.
- **Decisiones**: el adaptador tiene un tercer método `obtener_miniatura(info)` (para que el doble no use red). `descargar` ya está implementado en real y en el doble (el doble escribe un WAV sintético de `duration` s, máx. 60) para que 0048 lo reutilice; sin pruebas con red de descarga. Directo = `is_live`, `is_upcoming` o `live_status` en `is_live`/`is_upcoming`/`post_live`; un `was_live` ya terminado se acepta (es un VOD descargable). `info()` recibe la URL canónica `watch?v=<id>` (descarta `list=`, `si=`, `t=`). Los mensajes de yt-dlp se reenvían como `log` (nivel `debug` salvo avisos/errores).
- **Cómo probarlo**: `cd worker && uv run ruff check && uv run ruff format --check && uv run pytest` (tablas en `test_youtube_url.py` —usa el JSON compartido—, `test_youtube_metadatos.py` (32 casos), `test_youtube_errores.py` (21 textos), `test_youtube_miniatura.py`, `test_youtube_comando.py`; fixtures sintéticas en `worker/tests/fixtures/youtube/`). Prueba con red: `SHINOBI_TESTS_RED=1 uv run pytest -m red tests/test_youtube_comando.py` contra Big Buck Bunny (`aqz-KE-bpKQ`, Blender Foundation, licencia CC BY 3.0); solo pide metadatos y miniatura (comprobada: Deno resuelve el reto JS, ~5 s).
- **Deuda**: yt-dlp avisa de que falta `ffmpeg` incluso al pedir solo info (llega como `log` `warning`; es inofensivo, se podría filtrar). La heurística de título/artista es mejorable (p. ej. "Big Buck Bunny 60fps 4K - Official Blender Foundation Short Film" invierte título y artista: el usuario edita los metadatos antes de buscar la letra, ADR 0003). La descarga real no tiene prueba automatizada (la cubre 0048).
